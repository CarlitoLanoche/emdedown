# Emdedown architecture

How Emdedown is built, how the Windows host and the web page talk to each other, and why things are the way they are.
For using the app, see the [README](../README.md) and the [user guide](../samples/Guide.md).

---

## 1. Overview

```
Emdedown.exe  (C# / .NET Framework 4.8 WinForms)
 ├─ embedded resources (gzip):  web/**  (UI bundle),  lib/Microsoft.Web.WebView2.{Core,WinForms}.dll,
 │                               native/{x64,x86,arm64}/WebView2Loader.dll
 ├─ AssemblyResolve → loads the WebView2 managed DLLs from resources
 ├─ extracts the matching WebView2Loader.dll → %LOCALAPPDATA%\Emdedown\runtime\<version>\<arch>\
 ├─ WebView2 control (Microsoft Edge WebView2 runtime)
 │    https://app.emdedown/*   → served from embedded resources (WebResourceRequested)
 │    https://file.emdedown/*  → local media files; ?read=1 → decoded document text
 └─ host ⇄ page messaging: postMessage JSON (request/response + events)

web/ UI (vanilla JS, ES modules, bundled by esbuild)
 markdown-it (+footnote, emoji, deflist, mark, sub, sup, custom math/wikilinks/tasks) → DOMPurify
 highlight.js (common set) · KaTeX (lazy) · Mermaid (lazy) · CodeMirror 6 (lazy, editor)
```

Process model at runtime (default, GPU off): the host `Emdedown.exe` plus the WebView2 browser process, a renderer, a
network utility, a storage utility and crashpad.

## 3. Build

### 3.1 Toolchain

- The build uses the C# compiler that ships with .NET Framework 4.x:
  `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (so it needs 64-bit Windows). It supports **C# 5 only**:
  no `$"..."`, no `?.`, no `nameof`, no expression-bodied members, no auto-property initializers, no `out var`, no tuples,
  no pattern matching. `async/await` is fine. Keep it that way, or move to an SDK-style `net48` project with the .NET SDK.
- References: `System`, `System.Core`, `System.Drawing`, `System.Windows.Forms`, `System.Web.Extensions` (JavaScriptSerializer),
  `System.IO.Compression(.FileSystem)`, WebView2 Core + WinForms (`.deps/webview2/pkg/lib/net462`).
- `/platform:anycpu`; the native loader is picked at runtime from `PROCESSOR_ARCHITECTURE` / `Is64BitProcess`.
- WebView2 SDK pinned: `Microsoft.Web.WebView2` 1.0.4129.50 (downloaded from nuget.org, SHA-256 checked).
- Node.js is needed at build time only. The first build needs an internet connection (npm packages and the WebView2 SDK).
- Don't name a method `Handle` in `MainForm` (it clashes with `Control.Handle`).

### 3.2 JS dependencies (exact versions, from `web/package.json`)

## 4. Runtime details

### 4.1 Startup

1. `Main`: hook AssemblyResolve, create `%LOCALAPPDATA%\Emdedown`.
2. `Run`: parse arguments into full paths. `--edit` sets `StartInEditMode` (opens in Split). `--uninstall` asks for
   confirmation and runs `Installer.Uninstall()`; it refuses while another instance is running.
3. Single instance: if the mutex is taken, send `"open|edit\n<path>\n<path>…"` over the pipe (2.5 s connect timeout,
   `AllowSetForegroundWindow(-1)`) and exit. If the pipe fails, keep retrying while trying to take the mutex (500 ms waits; an
   abandoned mutex counts as taken) for up to 20 s. A new window starts only once this process owns the mutex; otherwise it shows
   "already running but is not responding" and exits with code 3, so there are never two windows. The receiving window queues
   paths until the page has called `ready`, so files opened during startup are not lost.
4. `WebViewRuntime.EnsureAvailable()`: extract the loader, `CoreWebView2Environment.SetLoaderDllFolderPath`, check
   `GetAvailableBrowserVersionString()`; if no runtime is found, offer to open Microsoft's WebView2 download page and exit.
5. `MainForm`: restore bounds/maximized/background colour from `window.txt` (avoids a white flash), create WebView2, start the pipe server.
6. `InitWebView`: environment with user data in `%LOCALAPPDATA%\Emdedown\WebView2`, browser extensions off, and browser arguments
   `--disable-features=msSmartScreenProtection --disable-background-networking --disable-component-update`, plus
   `--disable-gpu --in-process-gpu` unless `settings.json` has `"gpu": true`. Extra arguments can be added with the standard
   WebView2 environment variable `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` (the test helpers use it for `--remote-debugging-port`).
7. WebView settings: DevTools only with env `EMDEDOWN_DEVTOOLS=1`; default context menus on (for spellcheck suggestions), trimmed and
   extended in `OnContextMenu`; zoom control, status bar, autofill, password saving, built-in error page and swipe navigation off;
   **browser accelerator keys off**, so Ctrl+F/P/R/F5 reach the page's own handlers.
8. Navigate to `https://app.emdedown/index.html`. JS `boot()` → `call('init')` → apply settings → restore a shutdown snapshot if
   present → restore the saved session (if "Reopen tabs on launch" is on) → open the launch files on top, the last one active →
   `call('ready')`, which flushes any queued `openFiles`.

### 4.2 Virtual hosts

- `https://app.emdedown/<rel>` → embedded `web/<rel>.gz`, decompressed and cached in memory (files < 4 MB). `chunks/` and `fonts/`
  get immutable cache headers.
- `https://file.emdedown/<encoded absolute path>` → streams a local file (`FileShare.ReadWrite | Delete`) **only for media and theme
  types** (`RawFileMime`: images incl. SVG, audio/video, `.css`, fonts; sent with `nosniff`). Any other extension gets 403.
  `fileUrl()` in host.js builds these URLs (each segment `encodeURIComponent`, so `C:` → `C%3A`). Only drive-letter paths are served;
  UNC and device paths get 403 unless they lie under a trusted root (see §7).
- `https://file.emdedown/...?read=1` → the `FileService.Read` result (read on a background thread via a deferral) as UTF-8 text with
  headers `X-Eol`, `X-MTime` (decimal ticks, a string), `X-Enc`, `X-Path` (URI-escaped), exposed via `Access-Control-Expose-Headers`.
  This is how the page opens documents (much faster than JSON for big files); it falls back to `call('readFile')`.
- `NavigationStarting`: anything outside `https://app.emdedown/` is cancelled; http/https/mailto URLs open in the default browser.
  `NewWindowRequested` is handled the same way.
- `ProcessFailed`: a renderer exit resets `ready` and reloads the page, at most 3 times per 60 s (then a message box and no more
  reloads). A browser-process exit shows a message box and closes the window.

### 4.3 Content Security Policy (`web/src/index.html`)

```
default-src 'self' https://file.emdedown; img-src * data: blob:; style-src 'self' 'unsafe-inline' https://file.emdedown;
font-src 'self' data:; script-src 'self'; connect-src 'self' https://file.emdedown; media-src 'self' https://file.emdedown;
object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'
```

Local `<video>`/`<audio>` load through `file.emdedown`; media on the web is blocked by `media-src`. `style-src 'unsafe-inline'` is
needed because KaTeX and Mermaid emit inline styles; `img-src *` allows web images in documents.

### 4.4 Data locations

`%LOCALAPPDATA%\Emdedown\`

- `settings.json` — written by the page via `saveSettings` (atomic). Only a folder opened explicitly (Open folder) is persisted as
  `folder`. The host also reads `recent`, `folder` and `session.tabs[].path` at startup to seed trusted roots, and `gpu`.
- `window.txt` — `x,y,w,h,maximized(0/1),#bgcolor`.
- `recovery.json` — written by the host only at Windows shutdown/sign-out (`sessionFlush`):
  `{at, drafts:{<draft key>: text}, session:{tabs, active}}`. Returned by `init` as `recovery`, restored by `boot()`, deleted via
  `clearRecovery` (or at `WM_ENDSESSION` when the shutdown was cancelled).
- `WebView2\` — browser profile. Its localStorage holds drafts: keys `draft:<lowercased path>` and `draft:untitled:<tabId>`.
- `runtime\<version>\<arch>\WebView2Loader.dll`.
- `guide\` — the built-in user guide, written on first use of "Open the guide".
- `themes\*.css` — custom themes (a README.txt is created the first time the folder is opened from Settings).

Installed copy: `%LOCALAPPDATA%\Programs\Emdedown\Emdedown.exe`.

## 5. Host ⇄ page protocol

Page → host: `chrome.webview.postMessage({ id, method, args })`. The host replies `{ replyTo: id, result }` or `{ replyTo: id, error }`.
Host → page events: `{ type, ...payload }`. Dropped files: `postMessageWithAdditionalObjects({ method: 'dropFiles' }, files)` → the
host reads `CoreWebView2File.Path` → posts `openFiles`. Messages from any origin other than `https://app.emdedown/` are ignored.

### 5.1 Methods (`MainForm.HandleCall`)

| Method | Args | Returns / effect |
|---|---|---|
| `init` | – | `{settings (JSON string), files[], edit, installed, isDefault, desktopShortcut, runningInstalled, version, themesDir, themes[], recovery (JSON string or null)}` |
| `ready` | – | marks the UI ready (enables close interception) and flushes queued `openFiles` |
| `saveSettings` | `json` | writes settings.json (atomic) |
| `readFile` | `path` | `{path, text, eol, enc, mtime}` (background thread); `mtime` is a decimal string (ticks exceed 2^53); `enc` is `utf8`/`utf8bom`/`utf16le`/`utf16be`/`ansi` |
| `saveFile` | `path, text, eol, enc?, mtime?, force?` | `{mtime, enc}`; converts to CRLF when `eol` is CRLF; writes in `enc`; atomic. If `mtime` is given and the file changed on disk, replies with error `CONFLICT` unless `force` |
| `pathKind` | `path` | `'dir'`, `'file'` or `'missing'` |
| `listFolder` | `dir` | tree `{name, path, dir, children[], truncated}` (Markdown files only, empty folders pruned); also starts the folder watcher. `truncated` is set after 5,000 files, 20,000 directories or ~3 s |
| `searchFolder` | `dir, query, matchCase` | `{results:[{path, name, count, matches:[{line, text, col}], score}], total, truncated, ms}`. A new search cancels the running one, which replies with error `CANCELLED` |
| `watch` | `paths[]` | sets the watched open files |
| `openDialog` | `dir?, filter?` | paths[] or null (multi-select). `filter: 'image'` → "Insert image" dialog with image types; otherwise Markdown/text |
| `folderDialog` | `dir?` | path or null (`IFileOpenDialog`) |
| `saveDialog` | `name, filter ('md'\|'pdf'\|'html'\|'docx'), dir?` | path or null |
| `saveText` | `name, filter, text, dir?` | path or null (dialog + write) |
| `exportPdf` | `name, dir?` | path; `PrintToPdfAsync` (backgrounds on, no header/footer, margins 0.7 / 0.75 in) |
| `exportDocx` | `name, html, dir?` | path (written on a background thread) |
| `saveImage` | `docPath, name, base64` | relative `images/<file>` next to the document |
| `openExternal` | `url` or `path` | URL → default browser (http/https/mailto only); path → opened only for safe extensions, otherwise revealed in Explorer (never executes programs) |
| `reveal` | `path` | Explorer `/select` |
| `setTitle` | `title` | window title |
| `setChrome` | `dark, bg` | dark title bar (DWM), form + WebView background colour, saves window.txt |
| `setFullscreen` | `on` | borderless fullscreen toggle; posts `fullscreenChanged` |
| `install` | `desktop` | `Installer.Install`; desktop shortcut created when `desktop` is true, removed when false; returns `{relaunch: !runningInstalled}` |
| `setDesktopShortcut` | `on` | adds/removes the installed copy's desktop shortcut (throws if not installed); returns whether it now exists |
| `relaunchInstalled` | `files[]` | stops the pipe, releases the mutex, starts the installed exe with the files, closes |
| `setDefault` | `docPath?` | `'set'` or `'settings'` (see §6.3) |
| `isDefault` | – | bool |
| `uninstall` | – | `Installer.Uninstall()`, then closes |
| `openThemesFolder` | – | creates the folder + README, opens Explorer |
| `guidePath` | `name?` (`Guide.md` or `Welcome.md`) | writes the built-in guide files to `%LOCALAPPDATA%\Emdedown\guide` when missing or different in size, returns the path of the requested one (the page then opens it as a normal document: command `guide`, start-page link) |
| `quit` | – | allows the close and closes |
| `closeAck` | – | no-op reply; the page sends it as soon as it gets `closeRequested`, which cancels the close watchdog while the page shows its own save prompt |
| `editorFocus` | `on` | the page reports focus entering/leaving the editor; formatting items are added to the right-click menu only while true |
| `unwatchFolder` | – | stops the folder watcher (Close folder) |
| `sessionFlush` | `settings, recovery` | answer to `sessionEnding`: writes settings.json and recovery.json (atomic) and releases the host's shutdown wait |
| `clearRecovery` | – | deletes recovery.json (after `boot()` restored it) |

Path-taking methods (`readFile`, `saveFile`, `pathKind`, `listFolder`, `searchFolder`, `saveImage`, `reveal`, `openExternal` with a
path) reject network paths outside the trusted roots with "Network paths are blocked for links in documents".

**Test-only:** with env `EMDEDOWN_DEVTOOLS=1`, any call may pass `testPath`; the next save dialog then returns it without showing UI.

### 5.2 Events (host → page)

| Event | Payload / when |
|---|---|
| `openFiles` | `{paths[], edit}` — from the pipe, drag and drop or a second launch; queued until `ready` |
| `fileChanged` | `{path, text, mtime, enc}` — a watched file changed (debounced 180 ms; text normalized; `mtime` is a string) |
| `fileDeleted` | `{path}` — after a 400 ms re-check (editors often delete + rename on save) |
| `folderChanged` | – — Markdown files or directories changed in the open folder (debounced 250 ms; dot-folders and skipped folders ignored) |
| `closeRequested` | – — ✕ / Alt+F4, or a WM_CLOSE from another program (e.g. Task Manager "End task", `CloseReason.TaskManagerClosing`). The page replies `closeAck` at once, settles unsaved changes, then calls `quit`. If the page sends nothing within 4 s, the host asks whether to close anyway |
| `fullscreenChanged` | `{on}` |
| `format` | `{cmd}` — a formatting item was picked in the right-click menu; `cmd` is `bold`, `italic`, `strike`, `code`, `link`, `h1`–`h3`, `bullet`, `numbered`, `check`, `quote`, `image` or `table` (→ `formatCmd()` in app.js) |
| `sessionEnding` | – — `WM_QUERYENDSESSION` (Windows shutdown or sign-out). The host pumps messages for up to 2.5 s waiting for `sessionFlush`; no prompt is shown |

## 6. Front-end behaviour

### 6.1 Rendering pipeline (`render.js`)

- `render(text, baseDir, asFragment)`: strips YAML front matter (shown as a key/value card; a simple parser for `key: value` and
  `- item` lists), then markdown-it (`html: true, linkify, typographer`) with plugins. Custom rules: `$…$` / `$$…$$` math (block and
  inline) → placeholder elements; `[[Target|Label]]` wiki links; task lists `- [ ]` → `<input class="task" data-task-line>`; heading
  ids (Unicode slug, de-duplicated across every emitted id) + outline list; `data-line` on block tokens (level ≤ 3) for sync scroll and
  search jumps; fences → highlighted code (`hljs.getLanguage` only, no auto-detect), `mermaid` → `.mermaid-block`,
  `math|latex|katex` → `.math-block`; tables wrapped in `.table-wrap`.
- **DOMPurify** (a private instance, see §7) sanitizes all output. Hooks prefix ids, filter classes and styles, rewrite relative `src`
  on `<img>`/`<video>`/`<audio>`/`<source>` (and `poster`) to `file.emdedown` URLs (keeping `data-orig-src`), drop `srcset`, replace
  network-path images with "Blocked network image", fix inline-SVG id references, add lazy loading and strip `target`.
  Renderer task checkboxes carry a per-session random `data-task-key`; checkboxes without it (hand-written raw HTML) lose
  `data-task-line` and are disabled.
- Full renders use `RETURN_DOM_FRAGMENT` (avoids serialize/re-parse). Live-typing renders use string HTML + `patch()`.
- `patch(container, html)`: matches top-level blocks by their HTML (with `data-line` stripped) from the start and from the end and
  replaces only the middle, so an edit replaces just the blocks it touched. Keys come from the undecorated HTML: `stampKeys()` records
  them right after a full render, before `enhance()` adds anchors, copy buttons and diagrams (skipped for texts of 3 MB and more).
  Unchanged blocks keep their DOM (and rendered diagrams); only line attributes are synced. Returns the changed nodes.
- `enhance(nodes)`: callouts (`> [!NOTE|TIP|IMPORTANT|WARNING|CAUTION]`), code copy buttons, heading `#` anchors. Math and Mermaid are
  queued in an IntersectionObserver (root = preview pane, rootMargin 1500 px) and rendered when near the view. `renderAllPending()`
  is awaited before print, PDF, HTML/DOCX export, copy and slides. Those commands, plus Insert table of contents and Go to heading, first
  call `ensureFresh()`, which re-renders when the editor text is newer than the preview (Edit mode has no live render).
- Mermaid: `securityLevel: 'strict'`, `htmlLabels: false` (plain SVG text, so the canvas → PNG conversion for Word isn't tainted by
  `<foreignObject>`). Its SVG output is inserted without a second DOMPurify pass (that pass would strip the labels).
- KaTeX: `output: 'htmlAndMathml'`, `throwOnError: false`; CSS loaded lazily (`katex.css`, woff2 fonts).
- Very large documents (more than 1,200 top-level blocks) get `.big` → `content-visibility: auto` on blocks.

### 6.2 App (`app.js`)

- **Tabs**: each tab owns a hidden `<article>`; preview scroll is saved per tab; the editor keeps an `EditorState` per tab (undo history
  kept). Dirty = `text !== savedText`. Drag to reorder, middle-click to close, Ctrl+Tab cycling, reopen closed (Ctrl+Shift+T). New
  documents are `Untitled-<n>` with the lowest `n` not used by an open untitled tab. Many tabs scroll inside `#tabs` (wheel); `#app` has
  `grid-template-columns: minmax(0,1fr)` so the toolbar never widens the window. A thin scroll bar (`#tabs-track`/`#tabs-thumb`,
  `updateTabsBar`) appears under the tabs when they overflow and can be dragged.
- **Toolbar**: sidebar · Open · Save · Undo · Redo | tabs (`#tabs-wrap`) · New · formatting buttons (`#format-bar`, Split/Edit only;
  `data-fmt` → `formatCmd`; Heading opens a menu; `.fmt-extra` hide below 1180 px, the whole bar below 860 px) · sync toggle
  (`#btn-sync`, Split only) | Read/Split/Edit · theme · commands · settings. `updateChrome()` disables Save when there is nothing to
  save, Undo/Redo by CodeMirror's undo/redo depth (only while the editor shows the active tab), and fades the mode switch when no
  document is open.
- **Modes**: `preview` (Read) / `split` / `edit`; Ctrl+E cycles. The editor is lazy-loaded on the first non-preview mode.
  Live preview debounce = `min(450, 40 + len/4000 + lastRenderMs × 1.5)` ms.
- **Sync scroll**: `scrollDriver` (`editor` | `preview`) is set by wheel/pointerdown/keydown/touchstart in a pane; only the driver's
  scroll events move the other pane, via `data-line` interpolation.
- **Split divider**: `applySplit`/`setSplit`, 10–90 %, snaps to 50 % within 1.5 %; right-click → menu (Reset to the middle, then
  presets); double-click → 50 % (detected as the second mousedown, because `body.resizing *` has `pointer-events: none` during a drag).
  In Split mode the editor text has no max-width (Edit mode keeps 900 px).
- **Files sidebar**: the folder is the one opened explicitly, or else the active file's folder. That automatic choice is skipped for
  "broad" folders (`isBroadDir`, see §9) and is not persisted. Tree with expand state, fuzzy filter box, auto-expands to the active
  file, refreshes on `folderChanged`. **Close folder** (× in the panel head, command `closeFolder`) clears the folder state, calls
  `unwatchFolder` and blocks the automatic choice until a folder is opened explicitly. A `folderGen` token makes a late listing
  for a closed or replaced folder be ignored.
- **Search sidebar**: host full-text search, results grouped by file; a click opens the file, scrolls to the line and highlights it.
- **Outline**: headings with scroll-spy (in Edit mode refreshed on an idle timer while the panel is visible); reading progress bar.
- **Status bar**: path (click → Explorer; flashes "● updated" on live reload), Ln/Col in the editor, words · reading time (230 wpm),
  the file's encoding · `CRLF`/`LF`, text size %.
- **Find in page** (Ctrl+F in the preview): TreeWalker + `<mark>` wrapping (max 5,000), Enter / Shift+Enter. In the editor Ctrl+F is
  CodeMirror's search.
- **Links**: `#anchor` scrolls; http/mailto → browser; relative Markdown files (any `MD_EXT`) → open in a tab (+ anchor); wiki links
  resolve by file name within the folder tree, else `<dir>/<target>.md`; `.svg` → in-app lightbox; other files → host `openExternal`
  (safe list or reveal). Network-path links show "Network links are blocked".
- **Task checkboxes** in the preview toggle the source line; if the tab had no unsaved changes, the file is saved at once. A box that
  cannot be matched to its source line reverts.
- **Images**: click → lightbox (wheel zoom). Paste/drop an image in the editor → saved to `images/` next to the document (untitled
  documents are saved first). The spot is marked in that document's own EditorState (`pendingField` in editor.js, mapped through
  edits) and the link is inserted there via `applyPendingInsert`, also into a background tab; if the tab was closed or its path changed,
  no link is inserted and a warning is shown. Image files that arrive via `openFiles` never open as tabs: in Split/Edit the active
  document gets `![name](relative/path)` at the cursor (`insertImageRef`, no copy); in Read mode they show in the lightbox. Images are
  never added to `recent`.
- **Drafts**: unsaved text is mirrored to localStorage (1.5 s debounce, one timer per tab; flushed when a tab is deactivated or closed
  and on quit) and restored with a banner on reopen. Autosave is per tab too. Untitled tabs persist across restarts via the session; on
  restore the draft is written under the new tab id and the session saved before the old key is removed. A new untitled tab is added to
  the session immediately. Untitled tabs marked `discarded` ("Don't save") are left out of the session and get no draft.
- **Saving** (`saveTab` → queued per tab → `saveTabNow`): only the text actually sent counts as saved; text typed while the host writes
  stays dirty, its draft is written at once and autosave is re-armed. The draft under the previous key (old path on Save As, or the
  untitled id) is removed after a successful write. Code already inside a tab's save (the conflict "Overwrite" retry) must call
  `saveTabNow`, never `saveTab`, or it waits on itself. The tab's `enc` is updated from the host's reply.
- **Settling unsaved work** (`settleDirtyTabs`): one Save all / Don't save / Cancel prompt used by Quit, Install (before relaunching
  the installed copy) and Uninstall; it loops until nothing unsaved is left. Closing a single tab loops the same way.
- **External changes**: a clean tab reloads silently (keeping scroll); a dirty tab gets a banner "Reload from disk / Keep my version";
  a deleted file gets a banner and autosave pauses for it (a manual save recreates it). **Save conflicts**: saves send the tab's last
  known `mtime`; on `CONFLICT` a manual save asks Overwrite / Reload from disk / Cancel, autosave shows a banner and pauses.
  Reload from disk asks before discarding text typed while the file was being read.
- **Close**: the host sends `closeRequested`; the page calls `closeAck` immediately, settles unsaved changes, saves session and settings,
  then calls `quit`. In-app **Uninstall** runs the same prompt after its confirmation and is abandoned on Cancel or a failed save,
  because it deletes the app data (drafts).
- **Shutdown**: on `sessionEnding` the page sends its settings and every unsaved text via `sessionFlush`; on the next start `boot()`
  puts the drafts back, restores the tabs (even when "Reopen tabs on launch" is off, tabs with unsaved work return), shows
  "Recovered unsaved changes" and calls `clearRecovery`.
- **Start page**: Open file / Open folder / New, recent list (up to 10 shown) with a per-entry × and "Clear list" (asks first).
- **About** (command `about`, link in Settings): version, portable/installed, data folder, renderer, libraries.
- **App element lookups**: chrome elements after `#docs` in the DOM (`#start`, find bar, status bar, palette, modal, lightbox, slides,
  toast, dropzone) are resolved once at module load into constants; do not look them up by id at use time (document ids are prefixed,
  but this keeps the app robust). `ask()` settles a previous pending dialog with `undefined` (cancel) before opening a new one.
- **Command palette** (Ctrl+Shift+P, ☰ button): sections in `SECTIONS` order — File, Edit, Go to, View, Export & share, App;
  "Recently used" (up to 4) on top when the query is empty; key chips; when searching, a flat ranked list with section labels. Modes:
  `commands`, `files` (Ctrl+P; `>` switches to commands, `#` to headings), `headings` (Ctrl+R), `themes` (live preview on arrow keys;
  Esc/backdrop restores the previous theme). Per-theme commands `theme-<id>` exist but are hidden from the list.
- **Settings** (⚙ button, Ctrl+,): theme cards (light and dark half each), Appearance switch (Light / Dark / Follow Windows), theme
  select (incl. custom CSS), font, size slider, line spacing, page width, default mode, sync scroll, autosave, line numbers, wrap,
  reopen tabs, GPU toggle (restart to apply), Install/Update (asks about the desktop shortcut), Open .md files with Emdedown, custom
  themes folder, Uninstall, "Shortcut on the desktop" switch (installed only), About link.
- **Themes**: `THEMES` in app.js lists 6 themes, each with a `light` and a `dark` version whose `id` is the `data-theme` value in
  theme.css. `resolvedTheme()` = theme + appearance (`system` follows `prefers-color-scheme`); `toggleDark` (moon button,
  Ctrl+Shift+L) flips `appearance` within the theme; print and PDF use the theme's light version (`printTheme()`). Custom CSS themes
  sit on GitHub light/dark: dark when the file name contains `dark`, `night` or `black`. Swatches are drawn from the colours in
  `THEMES`.
- **Slides** (`slides.js`): a slide starts at every HR (not shown) and every H1/H2. Sections taller than the 640 px slide area at
  22 px text are paginated (`fits` measures in the live `#slide` element; a heading is kept with the block after it); a single table
  or list too tall on its own is split by rows/items (`splitBlock`; tables repeat the header, `<ol start>` continues). Text starts at
  30 px and shrinks only as needed (a single oversized block may go below 22 px, down to 14 px). The 1280×720 stage is scaled to the
  window; keys, click (left third = back) and Esc/F5/q to end. Links inside slides open only http/https/mailto.
- **Popup menus** (`showMenu`, `#menu`): heading picker, split divider (Reset first, then presets), tab right-click (`tabMenu`: Close,
  Close other tabs, Close tabs to the right, Close saved tabs, Close all tabs, Copy file path, Show in Explorer, Save, New document,
  Reopen closed tab; `closeTabs` stops at the first Cancel).
- **Tooltips** (`#tip`): any element with `title` inside `#toolbar, #side-tabs, #sidebar .panel-head, #statusbar, #findbar` gets the
  app's own tooltip; on hover its `title` moves to `data-tip`, so code may keep setting `.title`. 450 ms delay, 40 ms when moving from
  a visible tip; hidden on mousedown/wheel/keydown.
- **Line formats** (`editor.js` `lineFormat`): heading levels, list types and quote replace an existing marker of their group and
  toggle off when every target line already has that format; multi-line selections skip blank lines; numbered lists are renumbered.
- **Other**: focus mode F11 (hides the chrome + fullscreen), slides F5, print Ctrl+Alt+P. Ctrl+wheel / Ctrl+= / Ctrl+- / Ctrl+0
  change the document font size (not WebView zoom). Alt+← goes back through visited documents. The page suppresses the context menu
  except in the editor, inputs, or when text is selected (keeps copy and spellcheck).
- **Right-click menu** (host, `MainForm.OnContextMenu`): removes browser items listed in `HiddenMenuItems` (back, forward, reload, save
  as, print, QR code, writing direction, link/image save items, …; Inspect only with DevTools on) and tidies separators. When the target
  is editable and the page last reported `editorFocus: true`, it appends Bold, Italic, Strikethrough, Inline code, Link, a Paragraph
  submenu (H1–H3, bullet, numbered, checklist, quote), Insert image…, Insert table; picking one posts `format {cmd}`. Labels carry no
  shortcut text: a `\t` in a custom item label is drawn as a glyph, not as a right-aligned accelerator.
- **Commands** (`command(...)` in app.js): open, openFolder, closeFolder, clearRecent, new, save, saveAs, saveAll, close, closeOthers,
  closeRight, closeSaved, closeAll, reopen, nextTab, prevTab, quickOpen, palette, gotoHeading, find, searchFolder, toggleSidebar,
  showFiles, showOutline, modeRead, modeSplit, modeEdit, cycleMode, toggleDark, changeTheme, appearanceLight, appearanceDark,
  appearanceSystem, theme-&lt;id&gt; (hidden), zoomIn, zoomOut, zoomReset, focus, present, print, exportPdf, exportHtml, exportDocx,
  copyHtml, reveal, copyPath, reload, settings, shortcuts, install, desktopShortcut, about, setDefault, uninstall, bold, italic, link,
  strike, inlineCode, undo, redo, insertImage, insertTable, insertToc, quit. Global keys are in `KEYMAP` (a window capture listener);
  editor formatting keys (Ctrl+1–3, Ctrl+Shift+8/7/C/., Ctrl+Z/Y) belong to CodeMirror.

### 6.3 Install and default app (`Installer.cs`)

**Install** (no admin rights, HKCU only): copies the exe to `%LOCALAPPDATA%\Programs\Emdedown\Emdedown.exe`; Start menu shortcut;
desktop shortcut only if "Also add a shortcut to my desktop" is ticked (off by default, in the welcome dialog and in the install
prompt). Registry:

- `HKCU\Software\Classes\Emdedown.md` (+ `DefaultIcon`, `shell\open\command` = `"exe" "%1"`, `shell\edit` → `--edit`)
- `HKCU\Software\Classes\Applications\Emdedown.exe` (FriendlyAppName, open command, SupportedTypes, icon)
- `HKCU\Software\Classes\<ext>\OpenWithProgids` value `Emdedown.md` for `.md .markdown .mdown .mkd .mkdn .mdx .mdwn`
- `HKCU\Software\Emdedown\Capabilities` (+ FileAssociations) and `HKCU\Software\RegisteredApplications\Emdedown`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Emdedown` (DisplayName/Version/Icon, UninstallString
  `"exe" --uninstall`, size, NoModify/NoRepair; no QuietUninstallString, because the uninstaller always shows dialogs)
- `SHChangeNotify(SHCNE_ASSOCCHANGED)`.

After installing from a portable copy, the page offers to set the default app, then settles unsaved work (Save all / Don't save /
Cancel; Cancel keeps the portable window running), flushes drafts and calls `relaunchInstalled` with every tab that has a file path.

**Uninstall**: deletes only Emdedown's own keys and values (an extension's default value is removed only if it equals `Emdedown.md`;
other apps' associations are left alone), the shortcuts, then a hidden PowerShell (`Installer.CleanupAfterExit`, `-EncodedCommand`)
waits for the Emdedown process to exit and retries removing the install folder and `%LOCALAPPDATA%\Emdedown` once a second for up to
120 s.

**Making Emdedown the default app (Windows 10 behaviour):**

- If `HKCU\...\Explorer\FileExts\.md\UserChoice` does not exist, setting the default value of `HKCU\Software\Classes\<ext>` to
  `Emdedown.md` works, so `SetDefault` does that and returns `'set'`.
- If a UserChoice exists (another app was picked before), applications cannot change it: Windows protects it with a hash.
  - `SHOpenWithDialog` with `OAIF_FORCE_REGISTRATION` only shows "To change your default apps, go to Settings > Apps > Default apps."
  - `SHOpenWithDialog` with `ALLOW_REGISTRATION | REGISTER_EXT | EXEC`, and `rundll32 shell32.dll,OpenAs_RunDLL <file>`, show
    "How do you want to open this .md file?" **without** the "Always use this app" checkbox.
  - `ProcessStartInfo { Verb = "openas" }` reports that no application is associated; launching `OpenWith.exe <file>` directly shows
    no visible picker.
  - Windows 10 shows "Always use this app" only when Explorer itself opens the picker. So `SetDefault` opens `ms-settings:defaultapps`
    and returns `'settings'`; the page shows the steps (Choose default apps by file type → .md → Emdedown) and "I've done it" re-checks
    `isDefault`.
  - Ideas if this is revisited: `IApplicationAssociationRegistrationUI::LaunchAdvancedAssociationUI("Emdedown")`; on Windows 11,
    `ms-settings:defaultapps?registeredAppUser=Emdedown` deep-links to the app's page.
- `tools/dev/show-openwith.ps1` reproduces the `SHOpenWithDialog` experiments.
- Running "Open .md files with Emdedown" from a portable (not installed) copy registers that exe's current path; moving or deleting
  the exe breaks the association.

## 7. Security model

- Documents are untrusted. All rendered HTML goes through DOMPurify; the CSP allows only `script-src 'self'` and there are no inline
  scripts. A private DOMPurify instance (Mermaid uses the shared default one) forbids `<style>`, `<form>`, `<button>`, `<textarea>`,
  `<select>`, `<dialog>`, `<iframe>`, `<object>`, `<embed>`, `<base>`, `<meta>`, `<link>`, image maps and every `<input>` except the
  renderer's task checkbox; reduces `style` to table `text-align`; keeps only an allowlist of classes; and prefixes every document
  `id` / `<a name>` with `mdv-` (`ID_PREFIX`) so content cannot collide with the app's element ids. `href="#x"` stays unprefixed;
  lookups add the prefix and exports strip it.
- Naming: the `mdv-` id prefix and the `window.MDV` test hook keep a short historical prefix from the app's earlier working name.
- Network paths (UNC, `//host`, device paths) are blocked for anything a document references, both in the page (`isBlockedRemote`) and
  in the host (403 / "Network paths are blocked"). UNC paths are allowed only under roots opened on purpose (startup files, pipe, drop,
  dialogs, watched files, and saved recent/session/folder entries); mapped drive letters count as local. Trust is per session and only
  grows.
- Navigation away from the app origin is blocked; links open externally only for http/https/mailto.
- Local links never execute programs: only passive types in `FileService.SafeOpenExts` (images, PDF, text/data files, modern Office and
  OpenDocument files, audio/video) open in their default app; everything else is revealed in Explorer. Linked `.svg` files open in the
  in-app lightbox, where embedded script cannot run.
- The host ignores messages that do not come from `https://app.emdedown/`.
- `file.emdedown` serves raw bytes only for media and theme extensions; documents are read as text via `?read=1`. Exports embed an image
  only after checking its signature (`imageDataUrl` in export.js: PNG/JPEG/GIF/WebP/BMP/ICO/AVIF, or well-formed SVG).
- No network use except images a document links to on the web; SmartScreen, the component updater and background networking are
  disabled.
- Test hooks (`testPath`, DevTools) work only with env `EMDEDOWN_DEVTOOLS=1`.
- The WebView2 SDK download in `build.ps1` is pinned by SHA-256.
- The single-instance pipe uses the default ACL with `PipeDirection.In`: only the same user can send paths, which is no escalation.
  Do not loosen it.
- Residual risk: a document can still fetch images from the web (`img-src *`), which reveals that it was opened.

## 8. Testing

There are no automated tests. Changes are checked by hand in the built app, helped by the scripts in `tools/dev/`:

- `relaunch.ps1 [-NoBuild] [-File x.md] [-TestMode]` — force-closes any running Emdedown, rebuilds (unless `-NoBuild`), and starts
  `dist\Emdedown.exe` with `--remote-debugging-port=9333` (via `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`). `-TestMode` sets
  `EMDEDOWN_DEVTOOLS=1` (DevTools and the `testPath` save-dialog bypass).
- `cdp.mjs eval "<js>"` / `cdp.mjs shot out.png` — evaluates JavaScript in the page or takes a screenshot over the Chrome DevTools
  Protocol. `window.MDV` exposes tabs, the active tab, settings, `openFile`, `cmd(id)`, `call(method, args)` and more.
  Native menus and dialogs do not appear in these screenshots.
- `measure.ps1 [-IdleSeconds 10] [-Label x]` — working set, private memory and idle CPU of the Emdedown process tree only.
- `serve-web.mjs web/dist` — static server on port 8731 to check the UI in a normal browser (host calls fail gracefully; `isHosted`
  is false).
- `show-openwith.ps1 -Flags N` — reproduces the Open With dialog experiments (§6.3).

> **Warning:** the app always uses the real `%LOCALAPPDATA%\Emdedown` folder. Running it for a test rewrites `settings.json`
> (recent files, session, theme) and can touch drafts. Before a test launch, check whether that folder exists and back it up; restore
> it afterwards. `relaunch.ps1` also force-closes a running Emdedown, which loses nothing saved but skips the save prompt.

Tips:

- `Process.CloseMainWindow()` arrives as `CloseReason.TaskManagerClosing`, not `UserClosing`. To mimic the ✕ button, post
  `WM_SYSCOMMAND` (0x0112) with `SC_CLOSE` (0xF060).
- File mtime ticks exceed 2^53: keep `mtime` a string in JS, never `+value`.
- `fetch(file.emdedown/...)` custom headers need `Access-Control-Expose-Headers`.
- Mermaid shares the default DOMPurify instance (one bundled copy): global hooks would prefix its marker ids and strip its classes.
  Document hooks therefore live on a private `DOMPurify(window)` instance in render.js. Don't re-sanitize Mermaid SVG (labels vanish).
- Canvas `toDataURL` throws on SVG with `<foreignObject>` (tainted), another reason for `htmlLabels: false`.
- When editing sources with a script, remember that `String.replace` treats `$$` in the replacement as a single `$`; use
  `split(a).join(b)` or a replacer function.
- Word renders the DOCX export (MHTML altChunk); LibreOffice does not support altChunk and shows it as blank.
- Measure only Emdedown's own process tree; WebView2 processes of other apps inflate naive `msedgewebview2` totals.

## 9. Known limitations

- **Not code-signed.** Windows SmartScreen may show "Windows protected your PC" (More info → Run anyway).
- **Default app when another app already owns `.md`** goes through Windows Settings (see §6.3). This flow has had little real-world
  testing.
- **No automated tests.**
- **No auto-update** (it would need the network). The version is hard-coded in `Program.Version` and the assembly attributes.
- **No ARM64-native testing.** The ARM64 loader is embedded; .NET Framework apps run x64-emulated on ARM unless 4.8.1 is present.
- The editor shows YAML front matter as a setext heading (CodeMirror's Markdown mode has no front-matter support). Cosmetic.
- **Huge documents are slow**: sanitizing is the biggest cost (a 5 MB stress document takes several seconds to open), and switching
  away from a huge tab costs a noticeable moment. Ideas: sanitize per block, render progressively, or virtualize.
- **ANSI files**: saving an ANSI file whose text now contains characters outside the code page switches it to UTF-8 (so no characters
  are lost) without a notice; only the status bar shows the new encoding.
- **Hung renderer**: an unresponsive (hung, not crashed) renderer is only caught by the 4 s close watchdog;
  `RenderProcessUnresponsive` is not handled.
- **Files sidebar and shallow folders**: `isBroadDir` treats drive roots, `C:\Users\<name>` and every folder with two or fewer path
  segments (e.g. `D:\Notes`) as too broad, so opening a file there does not fill the Files sidebar automatically; use Open folder.
- The save-conflict check is check-then-write: a change landing in the milliseconds between the `mtime` comparison and the write is
  overwritten.
- The host trusts the folder of every path the page passes to `watch`, and every path in `settings.json` at startup. Only the app's own
  scripts run in the page today, so this is fine, but a future script-injection bug would widen network-path access.
- `fuzzy()` is permissive (unrelated names can match, ranked lower).
- Spellcheck relies on WebView2/Windows defaults.
- Raw HTML in documents is deliberately restricted (no inline `style` except table alignment, unknown classes dropped, no form
  controls, ids prefixed). Web `<video>`/`<audio>` are blocked by the CSP.
- Mapped network drives (e.g. `Z:`) count as local for the network-path rule.

## 10. Decision log

| Decision | Why |
|---|---|
| WebView2 + .NET Framework 4.8 WinForms (not Electron/Tauri/.NET 8) | Both are part of current Windows 10/11, so the app is a single small exe with no runtime to install. A self-contained .NET 8 app would be ~60 MB or more. |
| Compile with the in-box `csc.exe` | No .NET SDK or Visual Studio needed; the only build dependency is Node.js. |
| Embed everything (gzip), extract only the native loader to AppData | One file, nothing else next to it. |
| Rendering in JS (markdown-it etc.) | Best-in-class offline libraries, shared with the export paths. |
| Per-user install, no admin | Anyone can install it. HKCU registration + Apps & Features entry. |
| Lazy CodeMirror/KaTeX/Mermaid | Fast startup. |
| Lazy math/diagrams on scroll + DOMPurify fragments + streaming reads | A 5 MB stress document went from 14.5 s to about 6.4 s to open, and from 4.4 GB to 1.3 GB of memory. |
| GPU off by default | About 100 MB less memory with equal or better smoothness for documents; can be turned on in Settings. |
| Default app via Settings guidance | Windows 10 forbids apps from changing a protected UserChoice, and app-invoked pickers hide "Always use this app". |
| DOCX via MHTML altChunk | No heavy JS docx library; Word renders it faithfully. |
| Print/PDF in the light theme version | Paper is white. |
| Prefix document ids with `mdv-` instead of renaming app elements | One hook covers headings, raw HTML and footnotes; app lookups and exports adjust in a few places. |
| Block network paths unless under a user-opened root | A document must not make Windows authenticate to a server it names; documents opened from a share still work. |
| Show linked `.svg` in the lightbox rather than opening it | In a browser an SVG opened as a local file can run script; as an `<img>` it cannot. |
| Preserve the file's encoding on save; `mtime` as a string; `CONFLICT` on a stale save | Reading a file must never silently change it; ticks do not fit a JS number. |
| Files sidebar not auto-loaded for broad folders (`isBroadDir`) | Opening `C:\readme.md` must not walk a whole drive or profile. Trade-off: shallow folders such as `D:\Notes` also count as broad. |
| UNC trust per session, grows and never shrinks | Simple model: anything opened on purpose is trusted for the rest of the run; recent/session paths are re-trusted at startup. |
| Unsaved work at shutdown goes to a host-written `recovery.json` | Windows gives only a few seconds and no prompt can be shown; browser storage may not reach the disk before the process dies. |
| Keep `style-src 'unsafe-inline'` and `img-src *` in the CSP | KaTeX and Mermaid emit inline styles; web images in documents are expected. |
